## 已完成的源代码改动

### Room 提交事实和导入恢复

- 新增 `BackupImportCommitMarkerEntity` 与 `BackupImportCommitMarkerDao`，表 `backup_import_commit_markers` 使用 `importId` 主键，保存 `mode` 和 `committedAt`。
- `AppDatabase` 升级到 schema version 11，补充 10→11 迁移和导出的 schema JSON；旧版本迁移链保持可用。
- `BackupService.importBackup()` 在同一个 `database.withTransaction { ... }` 内完成错题、复习记录、知识点、cross-ref 和 DataStore 导入；DataStore 导入成功后，marker 作为事务内最后一个 Room 操作写入。
- `FILES_PUBLISHED`、`ROOM_COMMITTED` 和 `PREFERENCES_COMMITTED` 的恢复判定只读取 marker，不再根据新图片是否被引用猜测 Room 是否提交。
- marker 存在时保留 Room 当前引用的文件，删除本次未引用孤儿文件，清理 staging、rollback、journal 和 marker；marker 不存在时先恢复 preferences snapshot，再删除本次新文件和临时目录。
- 导入失败时保留可重试现场：journal 损坏或 preferences 恢复失败不会假报回滚成功，也不会提前删除 staging 或新文件。
- `MistakeRepository.resetAllData()` 把瞬时 marker 清理纳入同一 Room transaction，避免清除学习数据后留下过期导入事实。

### 原子 journal

- `BackupImportCoordinator.persist()` 改用 AndroidX `AtomicFile`，按完整写入、flush、`fd.sync()`、`finishWrite()` 顺序提交；失败调用 `failWrite()`，保留上一个有效 journal。
- 启动读取支持 `.bak` 恢复；`.new` 单独存在时不视为已提交 journal。
- 主 journal JSON 损坏时返回 `CORRUPT_JOURNAL`，写入 `backup-import/journal.error`，并保留 journal、staging、rollback 与已发布文件等待诊断修复。
- journal 清理统一删除 AtomicFile 及诊断文件，避免手写“删除旧文件后再 rename”的空窗。

### DurableTextStore I/O 故障缝

- 为 `DurableTextStore` 提供最小 `DurableFileOps` seam：`mkdirs`、`writeTemp`、`sync`、`move`、`copy`、`delete`、`exists`、`read`、`deleteRecursively`。
- 生产实现仍使用真实文件系统；写入流程为 tmp 完整写入并同步、保护旧 target 到 bak、替换 target、成功后删除 bak。
- 任何中间步骤失败都会删除 stale tmp；旧 target 可恢复时恢复旧 body，无法恢复时明确返回 null，不会返回半写入正文。
- 读取忽略 tmp，只在 target 缺失且 bak 可恢复时恢复 bak。

### HEIC/HEIF 原始资产

- 新增真实备份导出/导入往返测试，分别构造 `.heic` 和 `.heif` 原始 bytes。
- 导出 `.tiji` 后删除本地行和图片，再导入并断言扩展名、路径引用和 bytes 完全一致；不进行解码或转码。

### 重置执行契约

- 新增 `DataResetDependencies`、`DataResetResult` 和 `DataResetCoordinator.execute(mode, dependencies)`。
- `LEARNING_DATA` 统一执行 Room/图片/运行时/AI 解题/追问/识别历史清理，再清理复习计划、快照和 check-in 偏好；保留外观、AI profile、视觉 profile、API key 和 keystore。
- `FACTORY_RESET` 在学习数据清理后继续清理全部偏好与 keystore alias。
- `TijiNavGraph` 的两个设置入口都调用同一个 coordinator；异常向 UI 传播并显示失败信息，不再显示假成功。

## 自动化覆盖

### 导入崩溃矩阵

`BackupImportCoordinatorTest` 覆盖 `MERGE`、`REPLACE` 两种模式和以下全部 journal 阶段：

- `VALIDATED`
- `STAGED`
- `SNAPSHOT_CREATED`
- `FILES_PUBLISHED`
- `ROOM_COMMITTED`
- `PREFERENCES_COMMITTED`
- `COMMITTED`

无图片矩阵断言每个阶段的 Room、preferences、staging、rollback、journal 和 marker 状态。有图片矩阵同样覆盖两种模式 × 七阶段，并断言：

- 未提交阶段删除新文件；
- marker 已提交阶段保留被 Room 引用的文件；
- 未引用的新文件最终删除；
- 原有文件不被误删。

另外覆盖：

- AtomicFile `.bak` 恢复；
- journal 损坏诊断且现场保留；
- `FILES_PUBLISHED` marker true/false 分支；
- 无图片、无新增行但 preferences 发生变化的导入；
- preference-only 导入完成后 journal 和 marker 清理。

### DurableTextStore 故障点

`DurableTextStoreTest` 注入并验证以下步骤：写 tmp 前、半写、sync、旧 target 保护 move/copy、新 target 替换、fallback copy、restore backup，以及完整成功路径。每个失败路径都断言不暴露 partial body，正常 I/O 恢复后可继续写入。

### 其他闭环

- `BackupHeicRoundTripTest`：HEIC/HEIF 原始 bytes 往返。
- `DataResetCoordinatorTest`：真实 Room、图片和 marker 清理；FACTORY_RESET 顺序和失败传播。
- `RoomMigrationTest`：v9→v10→v11 marker 表迁移。
- 既有 MistakeDraft/Asset、AI repair、复习、搜索、PDF 和导航 contract tests 保留并纳入全量回归；生产代码没有复制测试算法。
