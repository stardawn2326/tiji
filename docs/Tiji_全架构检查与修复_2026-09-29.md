# 题迹全架构检查与修复

## 范围与结论边界

覆盖 app 的数据、领域规则、后台任务、导航和页面状态、图片资产、公式缓存、PDF、备份恢复、密钥与构建发布；检查构建脚本、Manifest、测试和关键调用链。起始生产 Kotlin 164 文件、35,425 行，单元测试 39 类、设备测试 59 类（本轮增加并发与历史错误回归类）。清单与 SHA-256：`outputs/architecture-audit-inventory.json`。

这是全模块检查和现有自动化回归，不是对每种手机、网络、数据库规模和交错时序的穷尽证明。未将第三方 OCR 原生二进制逐行审计；未检查远程 GitHub CI 的实时状态。

## 已确认并修复

### P1：不同 Store 实例并发修改同一个正文文件

原 DurableTextStore 的 @Synchronized 仅锁实例。ViewModel 与服务各有 Store，操作同一个 `.tmp/.bak/.txt`；AiSolveHistoryStore 的读后写也只有实例锁。

复现：`DurableStoreConcurrencyTest.differentInstancesCannotOverwriteEachOthersTemporaryFile` 在第一个实例写入临时文件后暂停，第二个实例仍能进入并写同一文件。修复前实际失败日志：`outputs/audit-concurrency-reproduction.txt`。

修复：StoreFileLocks 按应用私有存储绝对路径分配共享锁，固定 128 个锁，避免追问请求目录数量导致锁表无限增长。DurableTextStore、AiSolveStateStore、AiChatStateStore、AiSolveHistoryStore 共用可重入锁；整次状态读写和历史追加/去重/删除都被保护。不同路径哈希碰撞最多增加串行等待，不混用数据。此锁是进程内机制，独立 OCR 进程仍使用原有结果文件协议。

### P1：启动恢复与页面初始化并行

MainActivity 注释说先恢复再展示，实际 IO 协程启动后立即 setContent，Room/偏好读取及用户操作可能与恢复重叠。旋转时还可能在正常导入未结束时进入恢复。

修复：等待恢复完成再初始化会话和页面；BackupService 为导入和恢复提供共同 Mutex，内部导入调用未加锁的恢复实现，避免重复加锁死锁。恢复失败或 journal 损坏时保留数据并明确提示，不继续创建可写页面。未成功初始化的 Activity 退出时不清理 AI 状态。

### P1：追问进程中断后可能一直处于运行中

追问服务 START_NOT_STICKY，旧持久化状态没有进程身份；重建 ViewModel 只要 running=true 就继续观察，但旧任务不会自动恢复。

修复：持久化会话 sessionId，ViewModel 恢复时同进程继续任务；跨进程遗留任务转 STOPPED，保留已收到的正文、提问和图片，并允许再次追问。旧数据缺少字段按中断恢复，兼容已有完整记录。

### P1：历史保存失败可从界面初始化或完成回调逃逸

已完成解题追加历史会复制图片；图片缺失、磁盘写入失败可能抛出异常。服务有错误处理，但 ViewModel 初始化和完成观察器缺少对应保护。

修复：共享历史追加错误处理，保留当前解题结果及失败提示；历史更新失败也不再从界面协程直接逃逸。新增缺失图片场景设备测试。

### P2：PDF 导出最终写盘阻塞主线程

WebView 排版与绘制仍在主线程执行，但 PdfDocument 最终 writeTo/flush 改到 Dispatchers.IO；完成后再关闭文档。保留原导出格式和页布局。

### 测试契约修正

- 复习旋转测试分别验证顶部 `2 / 2 题` 和底部 `2 / 2`，仍验证当前题、评分与记录数量。
- 参考答案改名后的测试按现有 `答案` 文案断言。
- 未知模型能力测试补齐 fake SSE 的 stop/[DONE]；不关闭生产代码的截断保护。

## 后续结构优化，不伪装成已修复

1. 主 ViewModel 和根页面职责集中、首次恢复仍有同步读写；应分领域迁移，保持现有业务契约。
2. 根页面订阅全量错题和复习记录；LibraryIndex 已在后台派生，但每日计划等仍有组合阶段计算。需要 100/1,000/5,000 题设备帧耗时与内存测量后决定查询下沉或分页。
3. 追问流每个增量都持久化多个正文槽，写盘频率偏高；后续可合并进度写入，但必须保留终态和中断内容。
4. 备份允许至 160 MiB 解压内容但使用 ByteArray 集合，低内存设备存在峰值压力；流式暂存重构需要专门大备份和故障注入测试。
5. PDF 最终写盘已移到 IO；WebView 绘制本身仍有主线程成本，需要大批量实测。
6. 数据重置与后台保存/分类等复杂交错场景、网络阻塞取消时延仍需补充专项压力测试；不能凭当前通过用例宣称完全无竞态。
7. versionCode 114 / versionName 1.0.0 重复使用不利于验收追踪；本轮交付使用独立文件名和哈希，不擅自变更签名。
