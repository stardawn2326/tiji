## 实施范围

本次按《Tiji_功能完善与冻结方案_UI修改前_2026-09-13.md》执行功能冻结前收口。范围集中在复习契约、错题库计划动作、首页进度数据源、删除边界和 CI 契约；没有新增页面、知识体系、笔记体系、报告、PDF 类型或 AI 模式，也没有进行视觉验收。

## 已完成改动

### 复习流程与 AI 诊断边界

- 从复习题页移除“先写答案、检查答案、答案诊断、诊断写回错因”整条链路，以及复习页对 AI endpoint、model 和 API Key 的依赖。
- 复习题保持单一流程：题目 → 查看答案 → 参考答案与解析 → 四档反馈 → 写入复习记录并进入下一题。
- 反馈卡片只在答案展开后组合；未展开答案时不会出现反馈操作。
- 最高掌握档位增加二次确认弹窗；取消只关闭弹窗，不写入复习记录。
- 复习状态按反馈结果明确设置为 0/1/2/3，较低反馈可以把已掌握题降级。
- 复习结果达到“已掌握”后默认移出自动每日复习队列；仍可通过错题库手动加入明日复习。
- 删除或归档的题目在统一复习会被识别为不可用并跳过，不继续进入答题页。
- 删除仅保留软删除语义，原有撤回与清理流程保持有效。

### 错题库批量动作

- 底部批量动作由“开始复习”改为“加入明日复习”。
- 动作只写入 `inReviewPlan=true` 和下一学习日时间，不立即创建复习会话或跳转页面。
- 重复点击会重新定位到下一学习日，行为幂等；已掌握题也可加入计划且不会清除掌握状态。
- 操作完成后显示“已加入明日复习”；打印入口继续固定走 PDF 导出流程。
- 详情页和批量编辑中的“加入计划”统一使用下一学习日时间语义。

### 首页进度单一数据源

- 新增 `MistakeProgressCalculator` 与 `MistakeProgressSummary` Domain。
- 统计只接收未删除、未归档记录，统一计算累计错题、已掌握、掌握率和各科数量。
- 科目名称统一去除首尾空格，空科目归入“未分类”；科目按总数降序、名称稳定排序。
- 首页不再从当前搜索或筛选列表计算进度，改为消费 ViewModel 暴露的汇总流。
- 首页学习进度卡调整为“累计错题 / 已掌握 / 掌握率”，各科行直接使用同一汇总结果。

### V2 协议和 CI 契约

- 删除没有其他调用方的复习答案诊断服务、卡片和对应测试，避免冻结范围继续保留诊断入口。
- 修正 `AiVisionServiceTest`：验证现行 V2 标记、结构分区和禁止残缺 JSON 的契约，移除对旧协议文本的绝对否定断言。
- 保留 AI 解题现有 V2、追问、重复检测、多图、备份、PDF 和设置能力。
