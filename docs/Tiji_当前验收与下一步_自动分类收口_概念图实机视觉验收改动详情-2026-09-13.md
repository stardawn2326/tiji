## 本轮解决的问题

修复了保存 Sheet 中“分类尚未完成就立即保存”时自动分类被丢弃的问题。此前界面协程在保存时递增 `saveMetadataToken`，本地保存方法也不会继续绑定原分类请求，导致 V2 解题保存后科目、题型、标签和难度可能保持空值。

现在一次保存只拥有一个分类任务，并在保存前后保持同一个 `taskId`：

```text
点击“保存为错题”
→ Sheet 立即打开
→ AiMistakeClassificationService 立即启动一次分类
```

分类先完成时，结果持久化到任务状态并回填 Sheet 中仍为空且未编辑的四个字段。用户先保存时，当前 Sheet 值立即写入错题库；正在运行的任务随后绑定新 `mistakeId`，只通过 `mergeClassificationMetadata(...)` 补充数据库中仍缺失的分类元数据。两条路径都不会重新发起第二次分类请求。

分类失败不会回滚本地错题。已保存记录仍显示，绑定记录可使用“重试分类（不重新解题）”；保存前失败时仍可手工填写并保存，保存后保留同一任务的重试能力。

## 状态机与数据保护

- `AiMistakeSavePhase.CLASSIFICATION_PENDING`：Sheet 打开后任务已登记，尚无错题 id。
- `CLASSIFYING_PRE_SAVE`：前台服务正在使用解题内容分类，保存按钮仍可用。
- `CLASSIFICATION_READY`：分类完成但尚未保存，结果以紧凑 JSON 持久化，供 Sheet 回填或后续保存绑定。
- `SAVING`：本地复制图片和写入 Room 的保存屏障。
- `CLASSIFYING`：已获得 `mistakeId`，分类结果返回后写入该记录。
- `CLASSIFICATION_COMPLETED` / `CLASSIFICATION_FAILED`：完成或失败结果可在进程重建后恢复。

持久化结果只包含科目、题型、标签/知识点和四档难度，不包含题目、答案、解析或备注。结果回写前重新读取最新数据库行，保留学习者已经填写的字段；新分类难度统一归一化为 `0..4`，历史难度 `5` 仍可显示和兼容。

另外修正了结构化 V3 历史数据映射优先级：保存 Sheet 明确输入的科目、题型和难度优先于历史结构化学习元数据，空字段才使用历史值作为 fallback。这样用户在 Sheet 中的修改不会被旧协议字段覆盖。

## 代码改动

- `app/src/main/java/com/tiji/mistakes/service/AiMistakeSaveStore.kt`：扩展保存/分类状态机，持久化分类来源与结果，支持保存前分类结果恢复和过期任务诊断。
- `app/src/main/java/com/tiji/mistakes/service/AiMistakeClassificationService.kt`：允许无 `mistakeId` 的保存前分类；分类完成后根据最新状态选择回填 Sheet 或绑定错题；失败时保留保存竞态中后来绑定的 id；增加结果编码/解码和可测试的完成状态迁移。
- `app/src/main/java/com/tiji/mistakes/ui/MistakeViewModel.kt`：新增保存 Sheet 分类任务入口；本地保存复用原 `taskId`，在结果先完成、保存先完成和失败三种时序下完成绑定/重试。
- `app/src/main/java/com/tiji/mistakes/ui/solve/AiSolveScreen.kt`：移除界面生命周期内的独立分类请求和失效 token；改为观察持久化任务状态，只回填未编辑空字段；立即保存不再取消后台分类。
- `app/src/main/java/com/tiji/mistakes/domain/ai/AiSolvedMistakeDraftMapper.kt`：保存 Sheet 显式元数据优先，V3 learning 元数据作为未填写字段的 fallback。
- `app/src/test/java/com/tiji/mistakes/AiMistakeSaveStateTest.kt`：新增保存前/保存后同一任务状态迁移、结果持久化四档难度归一化，以及保存 Sheet 元数据覆盖 V3 fallback 的回归断言。

V2 新解题、V3 历史读取兼容、追问分流和 PDF 两种输出边界保持不变。
