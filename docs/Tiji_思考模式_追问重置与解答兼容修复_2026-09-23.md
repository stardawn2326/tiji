# 思考模式、追问重置与解答兼容修复

日期：2026-09-23

目标仓库：https://github.com/stardawn2326/tiji

分支：`codex/blue-white-uiux-20260921`

## 改动

- AI 模型配置增加“思考模式”：默认、开启、关闭，按配置保存。旧配置保持服务商默认行为；选择开启或关闭后才发送对应参数，不按模型名称禁止图片或思考能力。
- DeepSeek 等兼容接口使用 `thinking.type`；阿里云千问使用 `enable_thinking`；OpenAI/Gemini 兼容接口使用 `reasoning_effort`。自定义接口采用 `thinking.type`，其支持情况取决于服务端；不支持时可选“默认”。不会把关闭失败伪装成关闭成功。
- 思考字段仍不用于答案展示，保留现有思考内容过滤。
- “本次解题”标题中间增加“清空”：停止当前解题和追问，清理当前页面草稿及结果；已保存错题、历史记录和模型配置保留。保存错题进行中暂时禁用，避免中途破坏保存。
- 移除解题页、拍照录题页及图片公共预览组件外侧的“重新处理”。点击图片放大后仍可处理、替换和删除图片。
- 追问长上下文改为应用私有请求文件传递，服务启动 Intent 只携带引用，避免把整段解答塞入 Binder 参数。文件不含 API Key，读取后删除；失效请求显示错误。对取消或清空后的迟到结果增加状态检查。
- 解题完成不再以“必须符合 V2”作为保留答案的条件。普通文字、Markdown 解答按已有文本展示路径保留，仍支持保存和追问。
- V2 JSON 支持缺少外层 TIJI 标记或带 Markdown 代码围栏的返回；结构化展示仍校验版本和分区。缺失的题干/步骤不编造填充。
- 图片解题未单独抽取题干时，保留原图与已返回的解答，允许用户补充题干，不因这一格式问题抛弃解答。

## 为什么会“不符合 V2”

V2 是应用约定的内容协议，不是模型服务通用标准。此前应用要求完整 TIJI 包围标记、schemaVersion=2 以及四个分区，并在不符合时抛异常。模型可能返回正确答案但未遵守该格式。现在结构化解析负责增强展示，不再决定可读解答是否保留。空结果仍报错；请求超时、输出截断等实际故障继续保留原有错误提示和已收到内容。

## DeepSeek 耗时说明

思考模式可能增加延迟，但不能仅凭“慢”判定根因。当前可靠模式还包含独立一致性检查，检查失败时可能修复并复验；服务排队、网络、输出长度也会影响总耗时。本轮提供开关，不擅自修改用户的可靠性模式，也没有调用用户的付费模型做速度测试。

参数依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[千问思考模式](https://docs.qwencloud.com/developer-guides/text-generation/thinking)、[OpenAI reasoning 参数](https://developers.openai.com/api/docs/guides/reasoning)、[Gemini OpenAI 兼容接口](https://ai.google.dev/gemini-api/docs/openai)。各模型对关闭思考的支持可能不同，由接口响应决定。
