## 交付边界

## 阻断问题与修复

上一版 marker 只能证明主 Room transaction 已提交，但 transaction 之后仍会执行 legacy tags 知识点同步和 parent sanitation，因此 marker 并不等价于整个导入业务状态完成。

本轮将所有属于本次导入最终结果的 Room 写入收拢到同一个 `database.withTransaction { ... }`：

1. 导入错题、复习记录、知识点和 cross-ref。
2. 写入 DataStore 导入偏好（DataStore 仍按现有跨存储补偿协议处理）。
3. legacy schema 的 tags → KnowledgePoint/cross-ref 同步。
4. 知识点 parent sanitation。
5. `backup_import_commit_markers` 写入作为 transaction 内最后一个 Room 写操作。

transaction commit 之后只推进 journal 阶段和清理临时资源，不再执行任何必须成功才能补全 Room 业务状态的写操作。因此：

```text
marker exists
=> 此 import 的 Room 最终业务状态已经完整提交
```

## 源代码改动

### `MistakeRepository`

- 新增 `syncKnowledgePointsForMistakesInTransaction()`，只在调用方已经持有 Room transaction 时使用。
- 保留公共 `syncKnowledgePointsForMistakes()`，由它负责开启 transaction 并复用事务内实现。
- 新增 `sanitizeKnowledgePointParentsInTransactionForImport()`，明确调用方已处于导入 transaction。
- legacy tags 同步、孤儿知识点清理和 parent sanitation 均在 marker 写入前完成。

### `BackupService`

- 将 legacy 知识点同步和 parent sanitation 移入主导入 transaction。
- 删除 transaction commit 后的 `syncKnowledgePointsForMistakes()` 和 `sanitizeKnowledgePointParents()` 调用。
- 保持 marker 为 transaction 内最后一个业务 Room 写操作。
- 新增共享 `finalizeCommittedImport()`，正常成功路径和启动 recovery 共用，不补写业务数据。
- committed recovery 在必要时先把 journal durable 地推进到 `COMMITTED`，再删除未引用新图片、旧快照中已不再引用的图片、staging 和 rollback。
- committed 清理顺序固定为：清理 transient files → 清 marker → 清 journal；任一步中断都可以重试。
- marker 缺失时继续恢复 preferences snapshot，再清理未提交的新文件；恢复失败保留现场，不报告假成功。

### `BackupImportCoordinator`

- 增加不立即删除 journal 的 `cleanupPublishedWork()`，供共享 committed finalization 使用。
- 保留 `cleanupPublished()` 的兼容行为，并由其复用新的资源清理实现。
- committed 清理支持删除 journal snapshot 中已失去引用的旧图片，同时保留当前 Room 仍引用的图片。

## 新增与更新测试

### P0 legacy 完整性

`BackupSchema2ImportTest.legacyImportMarkerMeansKnowledgeGraphAlreadyComplete`：

- 导入 schema 2 备份，包含 `tags = "旧版函数，旧版函数,旧版极值"`。
- 不预置 structured knowledge point 或 cross-ref。
- 断言导入完成时知识点、cross-ref 和 parent 状态已经完整，不依赖全局 legacy backfill。

### P0 committed recovery

`BackupImportCoordinatorTest.committedMarkerRecoveryDoesNotNeedPostCommitRoomMutation`：

- 人工构造 `FILES_PUBLISHED + marker=true` 和已存在的 Room 最终数据。
- recovery 返回 `CLEANED_COMMITTED`。
- 断言 knowledge points、cross-ref 不发生变化，recovery 不补写业务数据，只清理 orphan image、transient files、marker 和 journal。

### 既有矩阵保持

- `MERGE`、`REPLACE` × `VALIDATED`、`STAGED`、`SNAPSHOT_CREATED`、`FILES_PUBLISHED`、`ROOM_COMMITTED`、`PREFERENCES_COMMITTED`、`COMMITTED` 的无图片和有图片 crash matrix 继续覆盖。
- preference-only、0 image、0 row change、AtomicFile journal 损坏现场保留、DurableTextStore 故障注入、HEIC/HEIF 原始 bytes 往返、Data Reset integration 和 Room migration 测试继续保留。
- 未复制生产算法到测试代码。
