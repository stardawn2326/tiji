## 追问崩溃根因

从用户当前 API30 模拟器抓到题迹主进程崩溃：`PatternSyntaxException`，调用链为 `incompleteFollowUpForDisplay → followUpReplyForDisplay → AiConversationReply`。

两处用于 JSON 片段和 LaTeX 修复的正则把字面量右花括号写成了未转义字符。Android ICU 正则解析器拒绝该表达式，流式追问在显示内容时直接令主线程崩溃。两处均已转义修正。之前“仅打开追问弹窗”的测试未覆盖实际流式回复，这是当时未复现的原因。

新增 Android 回归逐字符渲染未完成追问包围标记、JSON 片段、公式与普通回复，并用用户授权的真实 DeepSeek 追问覆盖生产解析路径。

## DeepSeek 实测边界

- 使用应用内已配置的 `deepseek-flash`，密钥只在应用进程内读取和使用，未复制或写入日志、文档、仓库。
- 题目为“计算 12×13，并简要说明计算过程”，比较已保存的默认思考配置与临时关闭思考参数。测试不会覆盖已保存的模型配置。
- 首轮总耗时：默认约 15.8 秒，关闭约 1.2 秒；默认明确返回了 reasoning 阶段数据。首轮首次答案时间的统计将 JSON null 计入，已修正统计并复测；上述总耗时不受影响。
- 同时确认可靠模式会额外发起独立校验，历史日志中一例解答约 71 秒、后续检查约 80 秒；总等待不一定都来自第一次解题请求。
- 简单文本题有限样本不能代表所有图片题和服务负载。没有擅自缩减模型输出上限或禁用用户功能。
- 最终复测：默认总计 13.063 秒、首个答案 12.155 秒；关闭思考总计 1.902 秒、首个答案 0.473 秒；关闭思考后的追问总计 1.285 秒、首个答案 0.445 秒。默认首次 reasoning 数据在 0.403 秒收到，其后约 12 秒没有答案正文；关闭模式未收到 reasoning 数据。
