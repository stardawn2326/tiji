# Tiji 设置重构与复习交互改动详情

日期：2026-09-12

依据方案：`Tiji_复习交互阶段验收与下一步收口方案_2026-09-12.md`

执行分支：`codex/v1.4f-ai-solve-core`

本轮代码基线：`677e4f5`（设置列表、复习会话恢复和首版横滑已合入的版本）

## 1. 执行边界

本轮启用已有的 `tiji-api30.avd`，设备序列号为 `emulator-5556`。没有重装安卓系统、创建第二套 AVD 或修改 API 35 模拟器；API 30 是运行验收目标，不是重新安装一个安卓系统。

本轮按方案收口以下内容：

1. 把复习横向切题从“松手后直接换题”改为跟手的页面位移动画。
2. 让按钮导航、横滑导航和评分后的自动推进共用同一个切题入口。
3. 将题目页底部的上一题/下一题按钮收敛为轻量图标控件，同时保留文字语义和 48dp 触控区域。
4. 移除复习页永久横滑提示，改由左右方向图标提供持续可见的操作线索。
5. 每次题目切换后把题目 `LazyColumn` 滚动位置恢复到顶部。
6. 恢复五个一级页面之间的方向性滑入/滑出转场；设置、知识点、详情等二级页面继续使用原有的二级转场节奏。

没有改动数据库 schema、复习调度算法、评分写入协议、AI 请求协议、OCR 模型、PDF 导出协议或五个一级页面的路由结构。

## 2. 具体实现

### 2.1 复习题目页：跟手切题动画

文件：`app/src/main/java/com/tiji/mistakes/ui/review/ReviewQuestionScreen.kt`

- 用 `Animatable<Float>` 保存题目容器的水平位移，只通过 `graphicsLayer.translationX` 移动内容，不动画化宽高、布局位置或滚动结构。
- 拖动过程中实时更新位移，手指移动多少，题目内容就跟随多少；这样不会再出现松手后突然跳页的感觉。
- 横向位移达到 `72dp` 才触发换题，向左进入下一题，向右返回上一题。
- 在第一题向右、最后一题向左时施加 `0.35` 的边缘阻尼，松手后回到原位，不会越过会话边界。
- 达到阈值后：当前题目沿手势方向滑出，状态切换后新题目从相反方向进入，再回到稳定位置。
- 页面切换使用 `220ms` 的 `CubicBezierEasing(0.23, 1.0, 0.32, 1.0)` 减速曲线；未达到阈值时使用无弹跳 spring 回弹。
- 读取系统 `ANIMATOR_DURATION_SCALE`。系统要求减少动画时，转场缩短为 `120ms`，保留方向反馈但降低运动量。
- 通过 `navigationAnimating`、`reviewSubmitting` 和 `autoAdvancePending` 防止评分、自动推进或连续点击造成重复切题。
- 评分成功后的自动推进改为调用 `navigateQuestion(1, cancelAutoAdvance = false)`，因此手动按钮、横滑和自动推进走同一条动画与状态链路。

### 2.2 题目页控件与滚动位置

文件：`app/src/main/java/com/tiji/mistakes/ui/review/ReviewQuestionScreen.kt`

- 底部普通题目使用 `‹ 题号 ›` 的结构：上一题和下一题是 `IconButton`，语义分别为“上一题”和“下一题”。
- 图标按钮保留 `review_previous`、`review_next` 测试标识，且 Material `IconButton` 的最小触控尺寸满足 48dp。
- 最后一题的“查看总结/完成”仍是带文字的 `TextButton`，因为它是结束动作，不是分页动作。
- 删除永久显示的“左右滑动切题，也可使用底部按钮”文案，避免题目页长期占用内容高度；底部方向图标和文字无障碍描述仍提供操作提示。
- 使用 `rememberLazyListState()` 管理题目列表，并在 `currentId` 变化时执行 `scrollToItem(0)`，避免从上一题中段切换到下一题后继承错误滚动位置。

### 2.3 会话状态与返回行为

文件：`app/src/main/java/com/tiji/mistakes/ui/navigation/TijiNavGraph.kt`、`app/src/main/java/com/tiji/mistakes/ui/review/ReviewQuestionScreen.kt`

- 题目页顶部返回只退出当前题目页，不清除未完成的统一复习会话。
- 返回复习一级页后，仍可看到“继续今日复习”，并恢复原题目索引及已答状态。
- 复习总结页退出时才清除已完成会话。
- “移出复习计划”仅在计划更新成功后清除会话，避免异步更新失败时丢失正在复习的内容。

### 2.4 五个一级页面转场

文件：`app/src/main/java/com/tiji/mistakes/ui/navigation/TijiNavGraph.kt`

- 恢复一级页面之间的方向性 `slideIntoContainer` / `slideOutOfContainer`。
- 使用现有 `pageSlideDirection()`：向右侧一级页面前进时从右向左进入，返回时从左向右进入。
- 一级页面进入与退出统一使用 `260ms`，与历史设计证据 `d816dafe` 的转场节奏一致。
- 二级页面保持 `220ms` 滑动转场，不把二级页面误当作底部一级导航。

### 3.3 API 30 设备证据与失败分类

设备：`emulator-5556` / AVD `tiji-api30.avd` / Android API 30。

- 本轮 Debug APK 已成功安装到该设备，包版本为 `versionCode=114`、`versionName=1.0.0`、`targetSdk=35`。
- 本轮定向执行 `ReviewQuestionUiTest` 的 2 个测试时，两个测试都在点击“开始复习”后等待 `review_show_answer` 或 `review_question_content` 超时，未进入本轮新增动画断言。
- 这不是“测试全绿”：API 30 上仍存在复习入口/数据可见性等待问题，需要在后续单独定位设备数据、Room 可见性或测试夹具生命周期。

此前在同一 API 30 AVD 上用同一组五类目标测试做过基线对比：

| 代码版本 | 目标测试结果 | 失败形态 |
| --- | --- | --- |
| `240f22f` | 8 个测试全部失败 | 复习/知识点入口等待超时，OCR 公式保留断言失败 |
| `677e4f5` | 8 个测试全部失败 | 与 `240f22f` 相同的入口等待超时和相同 OCR 输出 |

因此，现有证据支持的分类是：没有发现 `677e4f5` 相对 `240f22f` 引入的新 API 30 回归；API 30 的这组失败仍是尚未单独归因的环境/数据可见性/OCR 兼容问题。本轮新增的页面动画逻辑不能以这组未进入动画断言的失败宣称通过，也不能把 API 30 仪器测试标记为全绿。
