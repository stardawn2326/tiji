# 模型能力开放与录入界面修正

基线 ef7e0e7，继续使用 API30 环境。

## 界面

- 核对图片处理页：四角已经是主题色 L 形矩形角标，本次 APK 保留该实现；没有裁切圆点绘制。
- 错题库右上角由文档图标改为相机图标，沿用原录入入口。
- 录入方式由等宽大按钮改为可换行紧凑选项；保存按钮最低高度 52→48dp，空图上传区最低高度 160→112dp，功能和点击区域保留。

## 模型请求

- 移除基于服务商/模型 ID 的图片能力拦截。识别、解题、追问、视觉辅助与能力自检允许实际发出图片请求，不再根据名字丢弃追问图片。
- 视觉辅助配置展示全部服务商预设，不按模型名字过滤选项；推荐模型只用于填入 ID，标签改为“能力以实际请求为准”。
- 移除 DeepSeek 的 thinking.disabled、Qwen 的 enable_thinking=false，以及按服务商强制指定的 JSON 格式参数。保留题迹自身输出结构提示与解析，按服务商实际响应处理。
- 移除请求中的固定 max_tokens 与 temperature；包括自检之前仅 8 token 的上限。默认输出长度与采样行为由服务端决定，实际服务商仍可能拒绝不支持的输入或返回截断。
- HTTPS、API Key、输入完整性、超时/取消和错误处理不变；不改变保存数据格式或复习业务。

## 思考内容隔离

- 继续忽略独立 reasoning_content 字段；仅消费答案 content。
- 在所有流式答案发送给 UI 回调之前，增量剔除 think/thinking/reasoning/analysis 标记及其内容，处理跨分片标签、未闭合片段和嵌套情况；非流式内容经过同样过滤。
- 正常数学不等号、JSON 结构、解题步骤和解析保留。未标记的普通文本无法可靠判断是否为思考，因此没有用关键词误删正常解答。

## 验证

新增分片过滤测试和模拟服务契约：旧名单之外的视觉模型能到达 transport，body 包含 image_url，强制开关与固定上限不存在，流式回调只收到答案。首轮发现小于号紧邻思考标签的边界问题，修复后全部 209 项单元测试通过。

本轮没有调用用户真实服务商或消耗 API 额度；不宣称已验证某个实际模型具备视觉能力。API30 的 8 项界面回归全部通过，最终干净构建成功。adb install -r 返回 Success，MainActivity 启动成功。
