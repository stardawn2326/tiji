# 通用模型内容保留与断流修复

## 实测证据与范围

- 使用应用已有配置，对用户截图同类拉普拉斯变换题发起千问解题，以及千问、DeepSeek 追问。未导出密钥，未改动用户题库或配置。
- 千问追问实际出现 `{"math":"..."}`、`{"block":"..."}`、`{"paragraphBreak":{}}`，并混有多余闭合括号。旧解析只识别带 `type` 的片段，导致文字保留而公式和段落被静默丢弃。已用捕获样例复现测试失败。
- 本次 DeepSeek 追问使用标准片段格式，检查每个原文片段，作为兼容回归样例；不据此断言其他 DeepSeek 回复不会产生格式变体。
- 千问同题解题原文包含完整推导；虽有缺逗号等 JSON 错误，但该样例的现有回退解析保留了后半段。尚未取得手机截图那次原始回复，不能确认图一具体截断原因。
- 另确认共用传输层此前在没有 `finish_reason` 或 `[DONE]` 时仍可能接受提前结束的流。该缺陷通过模拟任意模型的传输测试复现，不作为图一已确认根因。

## 修复

1. 共用片段解析支持标准结构及简写的数学、块公式和换行片段，适用于所有模型，不检查模型名。
2. V2 同名分区不再只取第一段，按返回顺序保留后续内容。
3. 解题与追问均检查流式结束信号；提前结束最多续接一次，继续中断则明确失败并保留部分内容，不把它标记为完整成功。
4. 输出长度上限续接保留；第二次达到上限或断流时不再悄悄切成另一份非流式回答。
5. 不添加模型白名单，不改变思考模式，不删减正常解析和公式。
