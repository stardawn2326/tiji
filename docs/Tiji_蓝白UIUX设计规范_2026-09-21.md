# 题迹 · 蓝白 UI/UX 设计规范

## 本轮目标

用户授权全项目 UI/UX 自主重构，蓝白色为主，保留全部现有功能。沿用当前可运行基线 `c6d566b`，在 `codex/blue-white-uiux-20260921` 分支实施，不回退历史业务版本。

## 视觉方向

以清晰的学习工作台组织信息：浅蓝背景承托白色内容卡，深蓝文字负责阅读，明亮蓝色用于主操作、选中状态和掌握概览。参考技能中的扁平设计、原生触摸和无障碍原则；检索返回的青绿色教育配色不符合本次要求，因此采用按用户要求定制的蓝白配色。

| 角色 | 浅色值 | 用途 |
| --- | --- | --- |
| 主色 | `#2563EB` | 主按钮、选中、概览 |
| 主色容器 | `#E7F0FF` | 提示、标签、次级操作 |
| 页面背景 | `#F3F7FD` | 页面底色 |
| 卡片 | `#FFFFFF` | 内容、表单、弹窗 |
| 正文 | `#142C4B` | 标题和题目内容 |
| 次级文字 | `#52647D` | 说明、日期和状态 |
| 危险操作 | `#BA3547` | 删除与错误 |

深色模式保留，并使用独立的深蓝色表面和浅蓝色强调色。跟随系统、浅色、深色三个选项与持久化 key 均保留。

字号分为 32sp 概览、26sp 页面标题、17sp 分区、16sp 主体、14sp 次级正文、12sp 辅助文字。主控件最小触摸高度 48dp，输入框至少 56dp；筛选和 PDF 类型在空间不足时换行。全局卡片 18dp 圆角，重点容器 24dp，弹窗 28dp。

## 实施约束

- 不修改数据库、Repository、ViewModel、服务、AI 协议、调度算法和签名/SDK 配置。
- 移除的是失效的透明呈现方式和未使用的装饰组件；原有功能改为真实可见入口。
- 错题卡继续采用覆盖于数学 WebView 之上的点击层，左侧复选框单独占位；沿用原详情/选择回调。
- 全部功能数据来自现有状态，不增加展示用假数据，不植入远程字体或图片依赖。
- 验证只使用既有 `tiji-api30`；人工视觉验收交给用户，不把构建或点击测试等同于视觉验收。
